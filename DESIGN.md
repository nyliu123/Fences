# Fences Design System

## Overview

Fences is a compact Windows desktop utility for people who organize frequently used files without leaving the desktop. Its visual reference is smoked acrylic laid directly over wallpaper: recognizable as a Windows surface, but quieter than a normal application window. The product register is utilitarian. The memorable signature is real background blur with a cool graphite tint; controls, typography, and motion remain restrained.

The interface must not resemble a floating web dashboard, an opaque file manager, or decorative glass with strong gradients. `DESIGN.md` records intent; the runtime values are owned by `FenceWindow` and `BlurUtil` because this WinForms project has no shared theme layer.

## Colors

The Fence uses `primary` for the default native composition tint and a restrained translucent body so wallpaper remains perceptible. The title is rendered by a separate fully opaque overlay and never inherits the content surface opacity. Black and white remain the defaults, while each Fence may override title text, title background, body tint, and body transparency through the canonical Personalization dialog. Icons and item labels are always rendered at full opacity above the translucent body; file labels retain the existing dark text shadow so wallpaper color does not reduce readability. High-contrast behavior remains owned by Windows.

## Typography

Segoe UI remains the default typeface to match Windows shell typography. Microsoft YaHei UI is the Chinese fallback. Each Fence may override title and item-label families and sizes through Personalization; unavailable fonts safely fall back to Segoe UI.

## Layout

The existing grid and resizing behavior remain canonical. The default icon size is 48 px and the default item gap is 15 px; both values are independently adjustable from Personalization and update cell geometry without altering the saved Fence position or dimensions.

## Elevation & Depth

Depth comes from native acrylic blur, a translucent graphite wash, one subtle title highlight, the existing desktop shadow, and a one-pixel inner border. Do not add stacked shadows, opaque cards, or ornamental gradients.

## Shapes

Fence geometry defaults to rectangular edges. Personalization offers a per-Fence corner radius from 0 to 48 px, owned by `FenceAppearance.CornerRadius`, persisted with the other appearance settings, and shared by the native window region, background outline, and live preview. All personalization sliders ignore the mouse wheel; pointer dragging and keyboard arrows remain available.

## Iconography

The Fences application and tray icon uses a complete cool-graphite enclosure around three desktop-item tiles, with one restrained Windows-blue accent. The thick, closed silhouette fills the icon canvas closely so it remains prominent and legible at 16 px. The icon has no text, ornamental detail, or containing app-tile shape.

## Components

The Fence surface uses four coordinated native windows: a translucent acrylic body, a per-pixel transparent item layer for fully opaque icons and labels, a fully opaque title layer, and a nearly invisible pointer-input layer. The icon and title layers remain above the body during movement, menus, and focus changes; the pointer-input layer stays below the title and editors while receiving mouse and drop events. The runtime owner for per-Fence visual tokens is `FenceAppearance`; `DESIGN.md` documents its defaults, `PersonalizationDialog` edits a complete snapshot, and `FenceWindow` coordinates the renderers. Personalization uses a compact two-column workshop: a wallpaper-backed live preview on the left, scrollable white setting sections on the right, and a fixed footer for reset, cancel, and apply actions. The same borderless text control renders the title in both normal and editing states, so its font, alignment, and bounds never change; only a stationary left click enables editing and selects the original title, while any actual title-bar movement is treated strictly as a drag. Right-clicking first commits an active title edit, then clears the title control's focus, selection, caret, and editing visuals before opening the Fence menu. Enter, focus loss, or a click elsewhere in the Fence also commits the change. Fence items default to a 48 px icon inside a 96 px-wide cell with a two-line label area; personalized icon, spacing, and label sizes update rendering and hit targets together. Clicking an item icon toggles its full wrapped name, while clicking an item name first clears the full-name state and then opens the white, single-line inline editor. While the editor is open, the opaque item layer keeps the icon but suppresses the original name so the two text renderers never overlap. The editor width hugs the measured name like Explorer, and file-name editing selects the stem by default so the extension is preserved unless deliberately changed. A per-Fence blank-area context-menu toggle controls whether file extensions are shown. Hover and selection states keep the established Windows accent colors. Dragging an item exports its unchanged original path through the Windows file-drop contract and displays a background-free ghost at the original pointer offset; a successful external move removes it from Fence metadata. “移回桌面” remains the keyboard-accessible, non-drag alternative.

Within a Fence, dragging an item to a grid gap or row edge displays a slim insertion marker using that Fence's body background color on the opaque item layer. Its height and top alignment match the dragged item's selection bounds, including expanded names. Releasing commits the order to Fence metadata; leaving or cancelling clears the marker without changing order. Scrolling near the content edges exposes off-screen destinations. Locked Fences reject reorder, and item context-menu actions “向前移动” / “向后移动” provide the non-drag alternative. `FenceWindow.ItemReordering` owns the interaction and `ItemInsertionLayout` owns insertion geometry; existing cell sizes and external file-drop behavior remain canonical.

External file drags leave the source untouched while hovering; file moves begin only on drop. Drop failures restore earlier imports and queue error dialogs after the OLE callback returns so Explorer can finish its drag operation. The native item menu offers “以管理员身份运行” for executable files and shortcuts with existing executable targets. `ExecutableLauncher` resolves shortcut arguments and working directories and requests Windows elevation with the `runas` verb; cancelling the UAC prompt is a normal outcome.

Personalization's `FencePreviewPanel` shows a scaled, screenshot-like view of the current Fence's title and real project icons over the desktop wallpaper, with an approximate blurred/tinted body and opaque title, icons, and labels. Empty Fences use Windows stock icons. Preview dimensions preserve the Fence's aspect ratio, settings use the same grid metrics as the live Fence, and resizing invalidates the entire buffered canvas so no old frame survives. Batch personalization previews the first Fence's content.

Personalization headings stand alone without explanatory subtitle text. Pointer hover clears on leaving the Fence, while explicit selection remains independent. Context menus hit-test the invocation point: item actions appear only over an item, and the title counts as Fence background even during title editing. `DesktopWindowHost` attaches the body and icon layer to the native desktop host; `DesktopInputWindow` pins the title, pointer-input, and rename windows immediately above that host and below ordinary applications while allowing keyboard focus. Context-menu and editor activation never raises the Fence as an application group.

The system-tray icon is the persistent application-level control surface. Its menu mirrors applicable Fence settings as batch operations, including “批量个性化”, owns Fence creation, and provides a non-destructive application exit. “刷新” synchronizes original-path membership and refreshes the native desktop and Fence rendering; it can retry a failed native-view session. Individual Fence menus own only settings and actions for that Fence; they do not create other Fences.

Removing a Fence closes its body, title/item layers and editor windows before removing its original-path membership from the desktop filter. Failed removal reopens the remaining membership. Application exit closes all Fence windows before destroying the hosted desktop view and restoring the original Explorer icon layer. `FenceShutdown` synchronizes queued window removals with the compositor. Files remain at their original paths throughout.

Version 1.7 stores membership in `FenceInfo.KeepOriginalPaths` and leaves each real file, folder or shortcut at its existing path. `Fences.Native` hosts an `IExplorerBrowser` desktop-mode view with a per-path `IFolderFilter`; ordinary desktop icons are compacted in native monitor work areas. The original Explorer ListView is hidden only after a validated recovery journal is saved. `DesktopIntegration` owns startup, display changes, event-driven shell recovery and shutdown; `DesktopViewRecovery` validates window class, parent, process identity and start time before restoring the original layer. `OriginalPathMonitor` consumes filesystem notifications for external rename/deletion without polling. Legacy `FileDialogMonitor` / `DesktopFileAccess` remain compatibility code and tests, and are not started by 1.7. Native file dialogs read the unchanged original paths.


The hosted desktop uses actual desktop folder flags, so its View menu offers native large/medium/small icons, automatic arrangement, grid alignment and the Show desktop icons toggle. `DesktopMenus.cpp` combines view-owned controls and New commands with locally created desktop-folder context menus and installed Shell extensions, preserving command ID ranges and forwarding IContextMenu2/3 messages. Item menus remain native; background menus use the classic Shell menu rather than reproducing Windows 11’s newer first-level surface. The visibility toggle is scoped to the hosted view. `desktop-view-settings.xml` persists view flags, icon size, sort and manual positions; normal exit restores the original layer’s startup visibility. Rendering is wallpaper-backed; physical mixed-DPI layouts, dynamic wallpaper, actual Explorer restart and arbitrary third-party extensions require corresponding desktop checks.

The item context menu places a divider above “移回桌面”, immediately followed by “删除”; both actions are bold and share the existing desktop-release font. The Delete action appears only for an item, names the target in a confirmation with No as the default, and uses Windows recycling with an undo record. `FenceManager.RecycleItem` persists membership removal before recycling; failure or cancellation restores membership when the item still exists. A failed metadata write prevents the actual delete. Successful deletion clears stale selection/hover state and must not be reversed by exit recovery. “删除” is distinct from removing a Fence, which restores its contents to the desktop.

For valid Shell shortcuts, “打开文件所在位置” or “打开文件夹所在位置” precedes “以管理员身份运行”. The action opens the actual target's parent directory and selects the file or folder through the Windows Shell, without executing it or opening the stored shortcut's directory. Broken/non-filesystem targets and ordinary items do not offer this action. `ShellShortcut` owns shared resolution of the target, arguments and working directory; elevation continues to preserve the latter two values.

Transparent desktop items request their background through their parent's `WM_PRINTCLIENT` handler. This and `WM_ERASEBKGND` copy from one full-virtual-desktop wallpaper bitmap using screen coordinates, preserving each caller's clipping and viewport. Painting wallpaper directly into temporary per-item DCs produces misaligned tiles even when both messages share a handler. The bitmap is rebuilt on refresh/settings changes or virtual-screen bounds changes and released with the view. Wallpaper acceptance directly captures on-screen pixels in an isolated host after initial display, partial/full redraw, resize, filtering and icon-size changes. `PrintWindow` must not serve as the display oracle: its full repaint can mask the actual buffered-rendering fault. Tests do not modify system wallpaper settings.

## Do's and Don'ts

Version 1.7.5 presents desktop captions through a dedicated `DesktopCaptionWindow` using the same per-pixel layered presentation as Fence item text. Native layout, icon imagery, menus, drag/drop, hit testing and editing remain owned by the Shell view. Each caption region copies the matching wallpaper pixels before drawing one solid foreground, covering native ink underneath. GDI+ line layout uses native line height without reducing the font size. Selection does not add a separate blue caption rectangle. The surface raises with `SWP_NOACTIVATE`; the live native edit bounds are cleared to transparent and excluded from ordinary captions, preserving editor focus and stem-only selection. Native edit colors remain the system window foreground/background. Updates are event-driven and coalesced once; wallpaper and frame resources are released with the view. Live text opacity was accepted by direct user observation without capture; selected-background and edit-opening render snapshots check geometry and coverage only.

Version 1.7.6 keeps pointer interaction repair in `DesktopInteraction`: a plain background click clears selection and its focus anchor after native activation; a slow click on one selected label has a cancellable native-editor fallback. Shell image-change subscriptions refresh icon callbacks after active edits/drags finish. `DesktopWallpaper` reads current `IDesktopWallpaper` monitor paths and placement rather than relying solely on `PaintDesktop`'s process cache. Background broadcasts and menu actions invalidate both background surfaces; four bounded follow-ups cover asynchronous slideshow completion. `DragGhostWindow` owns a 15 ms tracking timer only while visible, keeping its top-level image moving across Shell targets independently of `GiveFeedback`.

Version 1.7.7 restricts wallpaper invalidation to successfully invoked `NextDesktopBackground` / `.SpotlightNextImage` verbs and `SPI_SETDESKWALLPAPER`; generic refresh and other menu/settings events leave the cache intact. `DesktopSelection` draws the same native list theme beneath the complete caption, including line-height expansion. Label clicks can initiate rename without a prior selection click. `RecycleBinIcon` consumes bin-content notifications, queries actual emptiness, respects per-user empty/full icon locations, and replaces only the stale recycle icon during the real paint pass. Numeric read-only diagnostics expose background reload counts and the actual painted bin pixels for the explicitly invoked live test; they never trigger painting or alter user selection.

Version 1.7.8 removes the second caption-background theme operation. `DesktopItemRenderer` draws one item backdrop and the existing Shell image-list icons; `DesktopCaptionWindow` copies those completed native pixels before drawing solid names. Caption geometry uses the same font/line-height calculation as the native backdrop, and focus/hot/selection changes invalidate the complete item surface. During rename, the caption HWND region physically excludes the native editor, while the list paint target excludes it as well; alpha-only clearing is retained but is no longer the only exclusion mechanism. Offscreen regression compositions use the actual native surface, the rendered caption layer and the native editor's print path. They verify rendering and geometry without claiming live desktop composition or text-opacity acceptance.

Version 1.7.9 replaces the failed desktop-child editor path with `DesktopRenameController` and the existing ordinary top-level `ItemEditorWindow`. Native `LVN_BEGINLABELEDIT` captures a ref-counted `DesktopRenameTarget`, cancels the child editor and posts an editing request. The target retains its Shell folder and PIDL, commits through `IShellFolder.SetNameOf`, and survives view reordering and reentrant Shell focus messages. Duplicate queued requests without a pending target leave the current editor open. Disposal closes the editor and releases its target before destroying the view. The visual layer now copies the entire item bounds, including icon and connecting space, into one per-pixel surface; it no longer joins a label-only patch to an icon painted by another window. Only the item currently being renamed is omitted from that layer. Tests distinguish shared colors from actual continuous coverage and keep live-display acceptance separate from offscreen rendering.

Version 1.7.10 retains that presentation pipeline while reducing its work. Native caption entries validate their PIDL bytes before reusing display names, and invalidate on collection/text/sort/rename changes. Font metrics are cached by font handle and window DPI. Hover invalidation unions the old rendered bounds and current bounds of the affected items. Native dirty regions accumulate until the managed presenter acknowledges the matching revision; changes arriving during presentation remain pending. The managed layer reuses its canvas/font/name buffer, skips unchanged revisions and redraws intersecting items in the existing selection order. Full refresh still handles layout, wallpaper and font changes. Each native popup owns one menu-command snapshot, rebuilt for the next popup rather than shared across openings.

Version 1.7.11 prepares desktop recovery/host discovery in `Start`, then creates the native view in `BeforeShowingFences` after membership migration. Initial exclusions are installed before Shell navigation; the previous native creation export remains compatible. Explorer stays visible until the filtered view is ready and recovery has been journaled. Original-path loads skip global Explorer flushing unless legacy stored files were recovered. Membership refresh reuses the source namespace snapshot; explicit refresh still reads it anew. Rename identity suppresses only the edited item's native background/focus painting while keeping selection and the opaque editor intact. `CanReleaseOriginalToDesktop` is shared by drag feedback and completion, allowing an arrow for a same-directory membership release while retaining native feedback for modifiers, invalid targets and non-desktop files.

Version 1.7.12 restores the native image-provider lifecycle. A combined posted request follows redraw resumption, list count/image changes and provider redraw notifications. It lets the native control paint to a disposable offscreen DIB outside `WM_PAINT`; that schedules deferred Shell image work without presenting native text or selection pixels. Requests made while the list is hidden remain pending. This is event driven, with no polling timer or extra extraction thread. The item painter queries cached original image dimensions through `IImageList2` and derives vertical padding from the native icon rectangle, keeping thumbnails proportional and aligned. The application activates Common Controls 6; dynamic interface discovery preserves DLL loading in older unmanifested test hosts. Caption presentation, membership and rename contracts are unchanged. Mixed-file acceptance reads the completed production surface before requesting the native reference and also checks that the presented layer contains the same opaque icon pixels; text-opacity acceptance still requires direct observation.

Version 1.7.13 obtains rename bounds after native layout, because `LVN_BEGINLABELEDIT` can still expose an initial temporary 16384-pixel rectangle. The native editor is allowed to finish layout while showing is suppressed; a posted completion captures its geometry, cancels it and opens the ordinary opaque top-level editor. The editor retains the native width and initial vertical padding, wraps text and resizes vertically within the working area. Its original vertical anchor is restored when content shrinks. Partition editors use their configured name-column width. The original four-argument editor constructor preserves single-line behavior for existing callers.

Version 1.7.14 puts scrollbar geometry/input in `FenceWindow.Scrolling`. Overflow reserves a gutter shared by painting, hit testing and insertion layout; the thumb is composited into the real layered background and capture ends on mouse-up/capture loss. Rename completion captures the deactivation reason before Shell calls can change focus, deselects only the edited identity before ending edit-mode presentation, and retains both old/new PIDLs through asynchronous rename updates. Stationary stale hover is masked consistently in native painting and caption decoration until pointer movement or new input. Blank desktop clicks update the Shell selection model and clear the list focus/range anchor; one posted cleanup is guarded by an input epoch, so a newer selection or marquee is never overwritten. No selection-maintenance polling is introduced.

Shell owns icon caching and image-list updates. Fences draws from the hosted Shell view's image list rather than coupling application code to disk-cache serialization. Windows publishes [system image-list access](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shgetimagelist) and [cache-only image retrieval](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishellitemimagefactory-getimage); the latter is an available API, not an additional extraction path used on every frame.

The 1.7.4 native list custom-draw handler owns PREPAINT/ITEMPREPAINT/ITEMPOSTPAINT and does not delegate those stages to the hosted Shell desktop's label compositor. Visible items use the ListView's default icon and opaque label painting; excluded items skip drawing. All other Shell notifications, editing, image callbacks, menus and keyboard handling remain native. Real desktop acceptance launches the actual executable as a separate process without a pre-observation capture; reflection-hosted entry points and matching hashes are insufficient proof of the normal non-screenshot rendering state.

Version 1.7.3 reads a validated snapshot of Explorer's actual desktop through `IShellWindows` / `IFolderView2` before creating a production view. Namespace objects appear only when present in that snapshot; physical items directly in the user/public Desktop folders are also allowed so new files do not wait for Explorer's enumeration. The snapshot is refreshed on explicit view refresh. Startup inherits the original icon size and exact grid spacing, while later in-view icon size changes retain the original grid padding. If the source cannot be read reliably, startup leaves the original view available. Alpha-shadow text is explicitly disabled; labels use opaque white native text. Alpha probes run only after all direct screen-capture acceptance states, since a probe that sends `WM_PRINTCLIENT` can mask a normal-display fault.

The native desktop host routes keyboard messages through `IShellView::TranslateAccelerator` using a managed message filter scoped to the hosted view and its descendants. The host supplies plain F5 refresh when the view leaves it unhandled; unrelated application windows keep their existing keyboard handling. The filter is removed before disposal. Wallpaper pixels are stored in a 32-bit DIB with alpha explicitly set to 255 before background copies, and native item custom draw uses opaque white text with alpha-shadow text disabled. Completed 32-bit item buffers have alpha repaired after GDI drawing and before composition. Screen-capture acceptance checks opaque white glyphs in each label, alongside wallpaper continuity; background paint tests verify opaque alpha separately.

- **Do:** Keep wallpaper perceptible below the opaque black title bar while maintaining readable white titles and item labels.
- **Do:** Preserve Windows-native interaction and localization conventions.
- **Don't:** Use blur without a tint and legibility overlay.
- **Don't:** Introduce decorative animation or reshape unrelated dialogs.

The public application/assembly name is `Fences`, defined for UI captions by `Program.AppName` and for build output by `Fences.csproj`. The existing `NoFences` source namespace remains compatible with resource and reflection references. `AppDataPaths` owns the runtime storage root `%LocalAppData%\Fences` and its `Logs` subdirectory. Before starting the recovery process, `AppDataMigration` runs under the legacy recovery mutex and moves old `%LocalAppData%\NoFences` data into the new root, atomically rebasing stored-item and pending-release paths while retaining external paths and unknown XML fields. Migration can resume after interruption and never overwrites a colliding Fence. Legacy single-instance and recovery mutex names remain coordination identifiers; normal operation and exit recovery use the new storage path.
